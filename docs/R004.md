# R004 使用说明

本目录中的 R004 源码保留实际接口和原始逻辑。主适配器取自六个复杂件使用的 R008 工作版本。它包括当前的 `drawing_roundtrip` 视图工厂、采集器和投影制式参数。[执行适配器](../src/solidworks_main_skill/backends/solidworks_automation/r004_execution_adapter.py)

## 源码入口

| 阶段 | 入口 |
| --- | --- |
| 组合推理与计划 | [`ReviewedCompositionInput`](../src/solidworks_main_skill/reasoning/r004_contract.py) → [`reason_composition`](../src/solidworks_main_skill/reasoning/r004_composition_reasoner.py) → [`plan_composition`](../src/solidworks_main_skill/reasoning/r004_planning.py) |
| 执行绑定 | [`r004_execution_binding.py`](../src/solidworks_main_skill/backends/solidworks_automation/r004_execution_binding.py) 校核输入、工序和原生支撑要求，原生调用入口为 `R004ExecutionAdapter.execute`。 |
| 受控工厂 | [`owned_adapter_factory`](../experiments/three_view_reconstruction/run_r004_q01_real_qualification.py#L185) 是六件经 R007 转接的现有入口。 |
| 原生身份与回读 | [R003 会话](../src/solidworks_main_skill/backends/solidworks_automation/r003_native_adapter.py) 提供 PID 归属和 ROT 绑定，[R003 采集器](../src/solidworks_main_skill/backends/solidworks_automation/r003_native_collectors.py) 回解持久引用并核对原生对象。 |
| 生命周期与图纸 | [文档生命周期](../src/solidworks_main_skill/backends/solidworks_automation/r004_document_lifecycle_diagnostics.py)、[清理](../src/solidworks_main_skill/backends/solidworks_automation/r004_cleanup_diagnostics.py) 和 [视图比较](../src/solidworks_main_skill/backends/solidworks_automation/r004_drawing_comparison.py)。 |
| 原有专项分支 | [可选原生证据传输](../src/solidworks_main_skill/backends/solidworks_automation/r004_native_observed_evidence.py) 的 `observation_context` 分支要求受控离线模拟。另保留原 R004 分支的 [槽工程图中心线扩展](../src/solidworks_main_skill/backends/solidworks_automation/r004_slot_drawing.py)。 |

## 离线验证

从仓库根目录使用已安装的 pytest。三个 R004 测试文件使用源码内合成输入和模拟后端。额外的 R003 检查使用注入的进程、会话和原生对象替身。

```powershell
python -B -m pytest -q -p no:cacheprovider -o 'pythonpath=src .' `
  tests/unit/test_cad_reasoning_r004_composition.py `
  tests/unit/test_cad_reasoning_r004_planning.py `
  tests/unit/test_cad_reasoning_r004_execution_binding.py `
  tests/unit/test_r003_native_collectors.py::test_exact_pid_exit_probe_rejects_ambiguous_output `
  tests/unit/test_r003_native_collectors.py::test_typed_persistent_feature_and_reopen_resolution `
  tests/unit/test_r003_native_collectors.py::test_reopened_sketch_dependency_uses_persistent_parent_and_support `
  tests/unit/test_r003_native_collectors.py::test_controlled_launcher_binds_only_new_pid_fake `
  tests/unit/test_r003_native_collectors.py::test_injected_owned_session_normalizes_lifecycle_without_real_com
```

发布副本导入实际适配器及工厂通过，上述选定测试 **119 项通过**。本次检查设置了 COM 模块导入阻断。有一项未列入命令的 R003 模拟出图测试会加载 `pythoncom`，本轮在导入处挡住了该项，未获得其测试结果。历史资格测试还可能依赖原机器配置、原始证据或私有 Git 历史。此次检查未启动 SolidWorks，`REAL_SW_INVOKED=NO`。[历史实验结果](EXPERIMENTS.md)

## 在自己的原生环境中调用

本节说明已公开的真实工厂接口。所需外部依赖包括 Windows、可用的 SolidWorks 安装与模板、Python COM 依赖和单独安装的原版 Automation。工厂从提供的 `backend_root/scripts` 加载原版 `sw_connect` 和 `sw_part`，并核验源文件及运行时 pins。[原版依赖与许可](../THIRD_PARTY_NOTICES.md)

1. 让 Python 能从仓库根目录和 `src` 导入包。准备当前零件已经确认的 `ReviewedCompositionInput`，通过原有推理和计划入口生成 `composition` 与 `planned`。
2. 使用下方配置字段定位本机安装。先用 `verify_backend(config)` 和 [`runtime_provenance(config)`](../experiments/three_view_reconstruction/r004_runtime_support.py#L33) 核对实际来源。建模计划的证据摘要须与当前工序对应。
3. 为新输出目录构造现有 `RuntimeReadAudit`。传入受核实的 runtime、输出内的 `cache_root`、`write_roots`、实际需要的 `allowed_roots` 和隔离评价数据的 `forbidden_roots`。允许范围包括使用的项目源码、本次输入输出和经过 pin 确认的外部文件。调用 `audit.bootstrap()`，在 `audit.active()` 中使用受控工厂。
4. 在原生操作已明确授权且符合原工厂条件时，调用 `owned_adapter_factory(config, run_id, live_authorized=True, acquisition={}, read_audit=audit)`。现有入口还检查 `RUN_REAL_SOLIDWORKS=1` 与是否存在其他 SolidWorks 实例。
5. 连接后调用 `execute(planned, composition, evidence_digests=...)`，由该入口创建新零件并执行计划。`evidence_digests` 以证据 ID 为键，以对应来源内容的 SHA-256 为值。按案脚本也可直接调用 `new_part`，再执行该脚本的后续操作。按任务调用 `collect_native`、`save_part`、`close_part`、`reopen_part` 和 `drawing_roundtrip`。结束时使用适配器的 `cleanup_documents` 检查并释放自有资源。

下方配置保留历史实测使用的依赖 pin，安装位置由使用者填写。SHA-256 只用于核对实际安装文件完整性。另一安装的文件和运行时有差异时，依据原入口的错误和实际版本核对。原始 Q01/Q02 资格配置、模型、图纸、回执和完整六件案例编排属于各自实验归档。
